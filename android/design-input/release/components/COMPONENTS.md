# Component and state contracts — Android-first reference

**Authored specification; partial reference coverage, no native acceptance.** Implement in Kotlin/Jetpack Compose under ADR 0014, not retired Views/JNI owners. Existing Go account/API contracts remain authority. A component contract is not proof that every state is rendered or exercised. [Coverage](../flows/COVERAGE.md) tracks remaining workflows; parent-owned [MOTION.md](MOTION.md) owns gesture/transition details and its checkpoint owns actual exercise evidence.

## Authority, units and ownership

Editable numerical authority: `tokens/soundq.tokens.json`; generated files are outputs, never a second palette. Paths below refer to that source, not independently maintained values. Reference dimensions map to dp for native layout; typography maps to sp with system font scaling. Preserve token generator mappings rather than pasting CSS px into Compose. OS WindowInsets are measured at runtime; `semantic.dimension.safeTop`, `safeBottom`, `safeCompact` are browser reference reserves, not Pixel measurements or native hardcoded system-bar heights.

Angular aerospace: `semantic.dimension.corner`, thin `semantic.dimension.border`, aligned `semantic.dimension.pageGutter` and `semantic.dimension.rhythm`; no pills, glow, blur or decorative shadows. `semantic.color.primary`/`selected` mean primary/current/selection; `semantic.color.secondary`/`focus` mean secondary/focus. Descriptive artist text uses `semantic.color.textMuted`, not secondary accent. Focus is not selection. Space Grotesk via `semantic.font.family.display` remains proposed normal-width UI type; technical values use `semantic.font.family.technical`. System fallback is required for unsupported glyphs; never shrink or condense text to recover width. Light/adaptive appearance is deferred, not an approved inverted palette.

Architecture: ViewModels project immutable component state; MediaController consumes the single Media3 service/timeline. UI queue copies, progress timers and notification toggles cannot become independent production truth. `trackId` identifies media; `occurrenceId` identifies one queue instance; collection membership and job IDs are separate identities. Every async result is fenced to account/endpoint/lifetime/request identity.

## Shared state vocabulary and precedence

| State | Visible/semantic contract |
|---|---|
| rest | Neutral text/surface/border; target remains discoverable. |
| hover | `semantic.color.hover` or `component.button.primaryHover` full target fill; pointer enhancement only, never required on touch. |
| focused | `semantic.color.focus` outline at `semantic.dimension.focusWidth`; visible independent of orange selected/current state. Do not clip it at row/sheet edge. |
| pressed | Full painted target feedback using `semantic.color.raised`; release/cancel removes it without changing selection unless command commits. Primary fill retains legible `component.button.primaryText`. |
| selected / checked | `semantic.color.selected`, persistent indicator plus selected/checked semantics, not color alone. Current media and selected filter are named separately. |
| disabled / unavailable | `component.button.disabledBackground`, `disabledText` and `semantic.color.disabledBorder`; expose disabled semantics, no command. Capability refusal explains why where useful; do not make an inert enabled control. |
| pending / loading | Stable target geometry, named progress and duplicate-submit guard; explicit cancellation only if operation supports it. Do not relabel pending as success. |
| error / refused | `semantic.color.error` plus readable reason and recovery; attach field error to field semantics. Preserve safe input and current listening identity. |
| uncertain | Request may have reached server: say not confirmed, reconcile exact target before offering safe retry, no automatic mutation replay. |
| confirmed / readback-failed | Confirmed write with failed refresh is not a failed write; distinguish and offer reload, not duplicate submission. |

Disabled wins over pressed; pending blocks duplicate activation; focus remains visible on focusable loading controls. Selected/current semantics persist through focus/press; error adds reason without erasing value. Each widget applies only relevant states: static text/art has no press/hover/disabled, passive progress no selected state, input validation no selected-tab semantics. Mutually exclusive choices use selected/checked, not an invented playing state. Announce state changes once, not every playback tick.

## C01 — Buttons and coherent icon actions

Anatomy: target, icon and optional visible label, focus outline, optional named progress. Bind target to `component.button.targetMin` and `component.icon.minWidth`/`minHeight`; icon to `semantic.dimension.icon`, `component.icon.padding`, `component.icon.strokeWidth`; corner to `component.button.corner`. These are minimum painted dimensions in both axes, not a tiny painted glyph with invisible padding only. Text actions expand and wrap; equal neighboring controls share painted size/baseline. Button motion uses `component.button.duration`; reduced motion follows MOTION.md.

Variants: primary submit/play; neutral transport/More; secondary nonprimary action; destructive named removal. Repeated actions are icon-led (Play/Pause, Previous/Next, Queue, More, Sort, Refine, Earlier/Later). Bottom navigation retains labels. Ambiguous/destructive/recovery actions retain words: “Remove from queue”, “Retry library”, “Apply filters”, “Sign in”. Do not reuse the plus for both competing New/Add actions. Icons are project-owned coherent SVG/vector shapes, not emoji or unrelated cute avatars; reuse the current icon vocabulary, no mixed optical weights. A missing required glyph is an asset-delivery gap, not permission to invent one per screen.

Expose role/name/enabled, toggles checked/pressed, expanded state for disclosure, and accurate next action (“Pause” when playing). Decorative child icon has no duplicate announcement. Touch release commits once; drag/cancel does not activate. Enter/Space activate native buttons, Tab order follows visible order; no hover-only menu. Loading label stays meaningful; disabled transport cannot pretend to play. Destructive actions identify object and scope and provide confirmation or valid Undo appropriate to operation.

## C02 — Text fields, search and secure entry

Anatomy: persistent external label; input surface; editable text/placeholder/caret/selection; optional leading icon; separately targetable trailing clear/reveal; supporting/error text. General form fields reuse `component.search.minHeight` as minimum geometry, `semantic.dimension.pageGutter` content track, `semantic.fontSize.body`/`semantic.lineHeight.body`, `component.search.border`, `component.search.focus`; enlarge vertically for scaled text. Search uses `component.search.inputMinHeight`, `component.search.iconInset`; icon/trailing controls use icon minimum targets. Text inset at leading/trailing edge must include reserved icon cells; text, placeholder and caret share exactly one content rectangle and baseline. No fake caret pseudo-element. Do not center text by translating glyphs independently of caret.

Field state model: pristine-empty, pristine-filled, focused-empty, focused-filled, composing, dirty-valid, dirty-invalid, pending, refused, uncertain, readback-failed, disabled. Placeholder is an example, never the sole label. Validation appears on submit or after a touched field loses focus, not an assertive error on each IME composition character. Error helper stays in flow, wraps and scrolls into view; errors are associated with their field. After failed submit focus the first invalid field and announce a concise form summary once. Server errors remain separate from local syntax errors. Pending guards submission but retains visible values; cancel semantics depend on actual request capability.

| Field | Keyboard / autofill / IME contract |
|---|---|
| Login email | Email keyboard, email/username autofill as supported, no autocapitalization; Next moves to password. Trim submitted email according to existing contract, do not rewrite text while composing. |
| Login password | Password keyboard and password autofill; no suggestions, autocorrect or capitalization. Done submits once if valid/not pending; never trim password. |
| Registration username | Text username input, username autofill where supported; Next. Preserve typed case; use current service validation, not invented normalization. |
| Registration email | Email keyboard/autofill, Next; current contract validation. |
| New password / confirmation | New-password autofill group appropriate to platform, explicit separate labels, Next then Done. Confirmation mismatch compares exact values. Existing Flutter minimum/validation behavior is baseline, not an invented password policy. |
| Library query | Search input, no credential autofill; Search acts on current query, clear is an explicitly named target. Retain selection/composition during list updates. |
| Discover query | Search keyboard, no autofill; Search invokes direct non-model search only. Explicit opt-in action required for research. |
| Source link | URI keyboard, no capitalization/autocorrect; paste allowed; Done validates/submits only on explicit supported action. Shared text is untrusted input, not an instruction. |
| Playlist/metadata editor | Text keyboard; Next advances fields, final Done follows explicit save contract. Metadata nullable blanks follow API semantics; title cannot be silently removed. Multiline description Enter inserts newline rather than accidental submit. |

Caret/selection: native TextFieldValue-equivalent value/selection/composition remain owned together; no selection reset to end on every render. Focus caret uses `semantic.color.focus`; selection fill uses that semantic role at a documented platform-appropriate contrast, native selection handles/toolbar remain operable. A tint/alpha adapter not yet tokenized is an integration residual, not a new independent numeric source. Preserve selection through reveal and validation; do not intercept paste/cut/copy in ordinary text. Secure reveal is a named Show/Hide password toggle with its own target; switching preserves field value/selection/focus and never submits. Revealed secrets remask on leaving auth/background/account switch; never log/capture real secrets, serialize password drafts, expose them as accessibility labels or force credentials into a design fixture. Respect platform secure-entry clipboard/autofill behavior instead of claiming browser proof. Commit autofill save only after actual acknowledged auth, never on synthetic fixture success.

IME composition must survive live filtering, validation and async completion. Do not submit while a composing region is active or mistake IME confirmation for a second form submit. Next/Done/Search and hardware Enter each have one event owner; keyboard event plus form submit cannot dispatch twice. Form uses a scroll container with runtime IME and system-bar insets, bring-into-view for focused field/error/submit, and no fixed player over entry. First Back hides IME; subsequent Back closes sheet/route under the current platform policy; predictive Back and edge-to-edge need Android tests. At short height/enlarged text, scroll header out, keep label/input/helper/submit reachable; do not shrink font to fit.

Draft lifecycle: retain nonsecret values/selection/touched/error and safe local next across transient sheet/navigation/configuration; query/sort/filter draft and scroll keyed by route/account. Password/confirmation remain ephemeral in-memory only while active auth flow; clear on success/logout/account-endpoint change/background policy and never restore after process death. Do not clear safe drafts for network failure. A pending request completion cannot navigate a departed/account-switched flow. Dirty metadata/playlist dismissal offers Discard/Keep editing where destructive loss would occur; filter drawer closure retains draft without applying it. Process-restored mutations reconcile server identity; do not resubmit on restoration.

Native IME/autofill/caret geometry, password manager, TalkBack secure text, composition, focus and keyboard insets remain unverified. Browser authored input geometry is not target-mobile proof.

## C03 — Masthead and destination navigation

Masthead: existing SoundQ emblem and wordmark, page context and explicit Settings action. Bind `component.masthead.minHeight`, `compactHeight`, `gap`; page gutter, brand typography and text tokens. Preserve local asset provenance and font licenses. Brand lockup must not compete with title or compress labels at enlarged text.

Navigation proposal: Home / Discover / Library / Playlists; player owns Queue, masthead Settings; nested Downloads/devices/Jam and applicable DJ access remain discoverable in relevant menus/settings/player. This adapts Flutter six-destination shell without waiving routes. Bind `component.navigation.minHeight`, `compactHeight`, `scaledHeight`, `gap`, `selectedText`, `semantic.fontSize.nav`, `semantic.lineHeight.navigation`. At enlarged text reflow two by two rather than shrinking labels; route meaning and selected label remain visible. Wide phone is not a persistent desktop sidebar.

States: rest/hover/focus/pressed/selected/disabled only where capability requires; route transition pending cannot lose current destination. Root tab switch retains each tab's query/filter/scroll and does not interrupt playback. Back pops nested detail/sheet before leaving route; auth lives outside signed-in shell. On return restore focus to opener, or route heading if opener disappeared. Distinguish root navigation from modal presentation in accessibility semantics. Error in a destination never disables unrelated listening/navigation.

## C04 — Track, collection, queue and job rows

Track anatomy: art/fallback, title, neutral artist, duration/state, trailing More; bind `component.row.minHeight`, `wideMinHeight`, `scaledMinHeight`, `art`, `wideArt`, `gap`, `currentBackground`, `selectedBorder`, `currentTitle`; title/artist typography via semantic font size and line height. Heights are minima, not clipping boxes. Whole track tap plays; More opens full metadata/actions; swipe never also plays. Long titles wrap with deliberate clamp only where full disclosure remains available. Disclosure shows full Unicode text, not tooltip-only recovery. Artwork duplicate description is decorative if adjacent identity is already announced; fallback does not imply downloaded/verified status.

States: loaded, current-playing, current-paused, preparing, selected, pressed, focused, stale-unavailable, disabled, pending-like, failed-like; lists additionally initial-loading, terminal-empty, query-no-match, error/retry, loading-more, partial-page-error. Unknown totals remain unknown. Initial skeletons are nonfocusable and grouped as one loading status; no decorative shimmer necessary. A stale account row cannot play from a retained callback. Server Like state is acknowledged, not a local optimistic success without pending/error handling.

Reveal/reversal/cancellation/scroll arbitration/one-open-row/tap-outside/keyboard alternatives and reduced motion are exclusively detailed in [MOTION.md](MOTION.md); use `motion.row.reveal`, `commitProgress`, `motion.gesture.slop`/`axisRatio`, not independent thresholds. Explicit More offers equivalent actions and native named accessibility actions supplement, not replace, discovery. No destructive full-swipe default.

Queue row uses occurrence identity even for duplicate track IDs. Earlier/Later disable only at actual boundaries; offer named actions plus drag if implemented, never drag-only reorder. Mutation announces new position once. Reference current-removal pauses and selects successor/prior last; final removal disables transport; Undo restores list without automatic resume. These are reference semantics to reconcile against native baseline, not accepted native behavior. Persisted queue restores paused. See `component.queue.duration` and motion contract for insertion/removal/reorder and stale completion rules.

Collection rows use collection ID plus acknowledged count and explicit empty/not-found states; membership occurrence is not queue occurrence. Import rows use job ID, status and progress; never label job completion as device download. Download management rows represent local artifact state and capability, not automatic playback browse. Playlist mutation feedback distinguishes added/skipped/refused/uncertain/readback-failed and account fences.

## C05 — Compact/full transport, seek and modes

Compact player: shared identity/art, progress, play/pause, separate Queue; `component.compactPlayer.art`, `minHeight`, `progressHeight`. Current title/artist and full player derive from same media/occurrence; duration/position never hardcoded per screen. Empty disabled compact player is a proposal differing from hidden Flutter mini-player. Hide redundant art at large text if needed, never shrink type. Keep transport target width and height, not just height.

Full player: `component.player.artMax`, `transport`, `gap`, `background`, `progress`, `duration`; title readable/wrapping, technical elapsed/duration, Previous/Play-Pause/Next, Queue and details. Media modes are named Shuffle on/off, Repeat off/all/one with selected semantics and textual description, not color alone. A boolean reducer flag does not prove actual queue ordering. Previous/Next capability comes from owner; cannot select outside actual timeline. Failure retains track identity and explicit Retry; preparation has cancel only if supported, never enabled fake Play.

Playback states: absent/disabled, resolving, buffering, playing, paused, seeking, ended, error, reconnecting. UI may display resolving as starting, but native buffering is not proof of playing. A single generation fences prepare/cancel/select/remove/account changes; stale result cannot restart audio. Transport command acknowledgment comes from service. Native pause/EOF/reconnect behavior must not be inferred from reference state changes. Background, modes and system actions all project same snapshot.

Seek anatomy: track/fill/thumb, elapsed/duration and accessible adjustable value. Thin visual track expands to `semantic.dimension.targetMin` hit area; do not make small progress paint the only touch target. Position clamps to known duration; unknown/live/unseekable disables seek without fabricated duration. During drag show preview without overwriting it with incoming ticks; commit once on release, cancel restores owner position; external track change cancels stale scrub. Keyboard arrows and Android accessibility set-progress/scroll actions are explicit alternatives with meaningful spoken time, not raw percentage alone. Increment policy follows target playback capability and must be documented/tested rather than invented into palette tokens. Keep duration and elapsed consistent with current selected track, and separate EOF seek/resume acceptance.

## C06 — Sheets, drawer, menus and modal recovery

Use bottom sheets for track actions/short choices, near-full sheets for player/queue, temporary right drawer for refinement; no phone persistent desktop rail. Bind `component.sheet.choiceMinHeight`, `bodyPadding`, `bodyGap`, `background`, `duration` and shared typography. Words remain on destructive, ambiguous and Apply/Reset actions; frequent actions icon-led. At enlarged text stack icon+label actions; full snap when needed; contents independently scroll above runtime insets. Selected choices expose radio/checked semantics, not only accent.

Named presentation states: closed, opening, dragging, medium, full, settling, closing, interrupted-retargeted. Gesture header has full target and explicit Close/Back plus non-drag snap alternatives. Scrim excludes background input and accessibility focus while modal; focus enters heading/first useful control, traps inside, restores opener/fallback after close. Nested player -> queue -> details returns previous sheet scroll/focus, not duplicate routes. Native Back cancels top presentation first; dirty editor uses loss confirmation; IME dismissal is not accidental destructive exit. Filter Apply commits one coherent draft; close/cancel does not mutate results and reopening retains draft. No event timeout may strand scrim/inert background after cancellation. Detailed drag/snap/velocity/retarget/completion/reduced-motion contract is parent-owned MOTION.md; do not duplicate its numbers here.

## C07 — Feedback, empty/error, progress and mutations

Bind content block `component.state.padding`, `semantic.fontSize.stateHeading`/`stateBody`, body line height; errors use semantic error plus text/icon, not color alone. “No tracks yet”, “No matching tracks”, “Could not load” are different states with respectively useful Add/Browse, Clear, Retry. Do not show a successful fixture count for a failed/loading read. Keep independent player/session available through Library errors. Pending actions reserve geometry; progress is determinate only with a real measured total. Network failure, auth expiry, refused capability, uncertain mutation and accepted-but-refresh-failed each have different recovery, not generic success toast.

Undo references exact operation/identity and remains reachable/readable; expiration policy if introduced is explicit and accessibility-aware, not an arbitrary animation timer. Do not auto-replay queued writes on reconnect. Destructive download delete says local-only; cache clear distinguishes reclaimed/deferred/failed and preserves pinned/decoder bytes. User action feedback uses polite status; urgent actionable errors may use alert once. Avoid announcing list changes or transport ticks continuously.

## C08 — System surfaces and platform adaptation

Metadata/artwork/media notification/lock screen/previews/Auto/voice/interruptions/reconnect each has an explicit separate M01–M09 gate in [coverage](../flows/COVERAGE.md). MediaLibrarySession owns canonical item/commands; notification, Bluetooth, headset, voice and car controllers cannot mutate local UI-only state. Android Auto uses platform driver-safe browse/search/play/auth-required patterns; never clone phone drawer/cards or permit car text-entry account forms. Screen-specific brand metrics do not override system templates. Validate controller/account scope and artwork credential-origin policy. Non-media application notifications are separate product/permission policy, not automatically admitted.

## Cross-component touch, text scale and accessibility acceptance

All interactive targets use `semantic.dimension.targetMin` in both axes, with nonoverlap and reachable painted feedback. Pointer hover is optional; hardware keyboard and TalkBack alternatives must reach every repeated or gestural action. Reading/focus order follows visible header -> entry/filter -> list -> listening -> navigation, adjusted for modal focus. Buttons expose role/name/state; headings/collections/field errors expose native semantics. Do not merge a row such that More or queue reorder becomes inaccessible. Current state and errors need non-color cues; exact composed contrast must be measured, not assumed from token names.

Declared reference sizes/text scales are in FIRST_CHECKPOINT.md. Preserve relative scaled type and wrap/reflow at enlarged text; reduce redundant art or re-group navigation/transport, not font size or line-height hacks. Inspect initial and scrolled complete rows plus anchored controls at compact/short height, 200% text, modal and error states; no-overflow alone is insufficient. Runtime system bars/IME/cutout must be consumed once, not double padded with browser reserve tokens. Focus rings/selection handles cannot be clipped. Reduced motion preserves state/orientation/actions through `motion.duration.reduced`; no gratuitous bounce, blur, glow or stagger.
