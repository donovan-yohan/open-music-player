# Native Discover — Hotate R3

Authority: source-only GET /discovery/search (q, limit=12, providers=youtube,soundcloud), neutral POST /source-selections (sessionId,candidateId,action=selected), POST /queue/items (sourceDecisionId,position=last), GET decision/list and existing download/job/Library reads. Backend queue here is intake, never the Media3 listening queue. No assist/research/audio preview request.

Ownership options: a separate Discover importer duplicates pending/receipt/recovery and job authority; passing a raw URL into link intake loses the server-owned selection/decision contract. Chosen: Discover owns only draft, explicit query generation and mounted inspection capability. Existing ImportRepository consumes that captured capability, owns both HTTP mutation stages and retained account receipt, and reuses its accepted job/Library read paths. One SoundQApi, no player calls. Source receipt uncertainty blocks starting another intake until authoritative decision recovery; this intentionally conservative single-outstanding flow does not promise R3 multi-uncertain parallel intake or process persistence.

Draft editing retires old results and tickets, never dispatches. Close invalidates mounted choices and pending search. Claimed but unentered source submissions are refused on route retirement. Entered mutations retain account-owned evidence across route exit. Decision save is never automatically replayed; unknown save recovers only by paged authoritative matching session/candidate reads. Known-decision queue recovery uses GET first or an explicit idempotent same-decision queue retry, never another decision. A SQL downloadJobId attachment alone is not publication: recovery verifies the existing Redis-backed job endpoint before acknowledging acceptance; a missing/unavailable job keeps the decision and Retry saved import available. No job correlation from a recent-jobs guess.

Ordinary search limit12 applies independently to ytsearch, YouTube Music and SoundCloud. Native decoding accepts their full disjoint36-row fanout within the backend50-candidate session ceiling; duplicates, malformed scalars and excess rows still fail. Query text (including literal ellipsis, Unicode and ampersands) is data, not a URL path traversal. Component traversal, foreign origin, credentials and redirects remain fenced.

Exact previously acknowledged decisions may outlive purged selection-session links. Known-ID readback accepts an omitted/null session only with the exact ID/candidate/selected action and preserves the captured local session. Create and unknown-list correlation still require the original server session; a conflicting present link fails.

The root owns the mounted Discover view/intake incarnation. Navigation and opening Imports close those exact capabilities synchronously, before destination publication and replacement intake creation. Child onDispose remains terminal idempotent cleanup. Claimed unentered decision POSTs and new second-stage queue POSTs are refused after exit; already entered decision responses retain account-owned evidence for explicit continuation. No automatic mutation replay is introduced.

Host regressions exercise real TLS/parser/repository boundaries and exact extracted ProductApp root action bodies. DiscoveryRootAdmissionTest compiles native mounted root OnClick witnesses held before child disposal; compilation is not native execution. Enlarged Discover and link-import journeys now use their lazy parent scroll actions to compose the status item/header before locating the target. All original mutation/job/Library/listening assertions remain; predecessor enlarged failures remain historical and successor native execution is pending.
